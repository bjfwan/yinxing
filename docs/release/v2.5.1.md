# 🍂 银杏 v2.5.1 发布

发布日期：**2026-11-24**
代码基线：`versionCode 26`

> 说明：自 v2.4.0 起源码不再公开。仓库中的源码停留在 v2.3.0，GitHub 自动生成的 `Source code` 附件为该快照，不含本版本程序源码。APK 继续免费提供并承诺永不收费，详见 [LICENSING.md](../../LICENSING.md)。

本版**没有新增功能，全部是修复**，重点是把「明明开了却说没开」这类说不清的权限状态拆开讲明白，并加固微信自动接听的节点读取与长时间运行后的稳定性。**发布说明中的「工程验证」指自动化测试，「验证边界」写的是没验到的部分，两者不混用。**

## 这一版修的是用户反馈里的问题

本版的修复清单不是拍脑袋排的，而是从**用户主动开启的诊断日志**里捞出来的真实失败样本：权限状态读错、更新装不上、微信用久了点不动、同名城市天气串了。每条都对应日志上报里的具体路径和错误码，改完再用回归锁住。

需要说清楚的是：**日志反映的是上报过的设备，不是全部设备**。所以这一版属于「针对反馈过的用户做特定优化」，不等于所有机型的同类问题都已经解决。如果你或家里长辈用着仍然不对，请在「设置 → 反馈问题」里说一句，或打开诊断日志上报——只有拿到新样本，才能判断是同一处没修干净，还是另一条路径。没有样本的猜测不做修复，避免用放宽匹配、增加重试的方式把问题藏起来。

## 权限与通知：说清到底缺哪一项

🔔 **通知拆成四项分别判定**：过去设置页把「通知」当成一个状态，只要 Android 14 的「来电全屏提醒」没开，整项就显示未开启——用户在系统里明明看到通知是开的，回到银杏还是红的。现在分开判定：**通知总开关 / 通知权限 / 来电通知通道 / 来电全屏提醒**，副标题直接写缺的是哪一项，点按直达对应系统页；只差全屏提醒时提示「已允许通知，还需开启来电全屏提醒」，不再含糊。

📞 **基础拨号只申请打电话权限**：首次启动的「必要电话权限」原来复用自动接听的整组权限，只想让老人普通拨号的家属会被挡在首页外。现在必要两项仍是「联系人 + 电话权限」，但基础拨号只申请、只校验 `CALL_PHONE`；自动接听保留完整权限与默认电话角色前置检查。

🚨 **跌倒求助单独授权**：原来复用整组电话权限，授权后还要回去把开关再拨一次；拒绝会直接跳系统设置，人工去设置开好了也不接续。现在用独立授权，同一意图逐项完成后直接启用；拒绝留在原页；用户明确点「去设置」时记住回访意图，回来就绪自动接续，离页或仍缺项就停止。

🙅 **拒绝不再强制跳设置**：电话、通知权限被拒后先留在当前页说明影响——「拨打和自动接听暂不可用，可以稍后再设置」——只有点「去设置」才跳转。永久拒绝仍保留修复入口。

🧮 **空结果不再当成已授权**：权限回调结果为空时 `values.all{}` 恒为真，仅部分授权也可能被误报成整组就绪；现在整组回调同时校验结果非空与实际系统权限，基础拨号与跌倒拨号各用各的回调。

## 微信自动接听与长时间运行

🧩 **节点归属与回收加固**：修了三类可复现的生命周期问题——取消后仍返回失败、导致调用方再次回收同一节点；无障碍查询把借用的 root 交给会回收结果的调用方；事件 root 混用借用与拥有节点、parent 链中间节点泄漏。这类问题会在长时间使用后表现为读屏异常或系统侧警告，现在所有权边界写成明确约定并有专门回归锁住。

📏 **节点读取加预算**：元素定位的递归补上深度、节点数与墙钟预算，首页根节点缓存改为独占持有，节点树扫描移出主线程（单线程队列、上限 4、同 tag 合并），避免微信界面异常时把主线程拖住。

📉 **卡顿归因修正**：线上「主线程卡顿」样本里绝大多数停在无障碍框架的等待调用上，而旧逻辑用本应用包名过滤「应用帧」，把 vendored 无障碍执行层里的调用方裁掉了，于是样本被误判成应用自身卡顿、日志只剩系统帧。现在改为排除平台前缀、保留栈顶 15 帧与第一个应用帧及其下 10 帧，恢复类指标拆成四个独立名字（睡眠、超长、空闲恢复、watchdog 自检），后续能分清「系统卡住」和「我们卡住」。

📞 **接听文案与替换确认精确化**：接听 / 拒接 / 免提 / 替换通话确认改成唯一精确文案；同一窗口同时出现「接新来电会挂断当前通话」和接听按钮时自动停手、只记录不点击，不再抢屏。

## 更新与设置

⬇️ **更新安装授权点一次就够**：以前点「安装」→ 去系统设置授权 → 回来还得再点一次安装。现在一次点击、一次接续：授权页返回后直接打开安装确认页；拒绝或取消可以返回，不会卡在死循环；打不开授权页时给出明确提示。

💾 **设置写入失败不再悄悄丢**：DataStore 写入异常以前从后台逃逸，页面还以为保存成功。现在捕获可恢复异常，页面明确提示「部分设置未能保存，当前选择可能仅本次生效」，取消与 Error 仍照常抛出。

🖥️ **默认桌面更换归类修正**：用户自己把桌面换成别的应用，不再被记成「设置银杏失败」；真正设置银杏失败仍保留原错误码。

## 天气

📍 **同名地点按坐标隔离**：同名不同坐标的城市原来共用退避与在途请求状态，一处失败会让另一处拿到过期结果。现在用「城市 / 坐标」统一身份，前后台共用在途请求，离线、失败、退避都校验坐标缓存。

🔎 **城市搜索错误分开提示**：城市不存在、网络异常、服务异常和退避等待分别提示，保留用户输入并恢复重试按钮，不再一律提示「检查城市名称」。

## 工程与架构

- 设置动作按职责拆成动作门面 / 电话授权 / 默认桌面三块；微信主动拨打的能力动作从会话控制器拆出，无障碍服务类从 3000+ 行降到约 280 行；`SettingsDetailController` 从 2655 行降到 100 行，页面各自保留定制。
- 首页公共模型（`AppInfo`、`HomeAppItem`、`HomeCardSize`）下移到 `data.home.model`，去掉 `data` 反向依赖 `feature` 的耦合；新增 Node 契约测试锁住分层。
- 新增公开站点白名单生成工具 `scripts/prepare-site.mjs`：逐文件白名单复制、拒绝符号链接与非空输出、复制后自动核对字节，避免把内部文档带进公开站点。
